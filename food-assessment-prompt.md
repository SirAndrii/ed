# Промпт для створення застосунку оцінювання продуктів

Створи завершений, готовий до запуску вебзастосунок для оцінювання того, наскільки складними підлітку здаються різні продукти.

## 1. Технології

Використовуй:

- React;
- TypeScript;
- Vite;
- звичайний CSS або CSS Modules;
- `localStorage` для збереження даних;
- Vitest для основних тестів;
- GitHub Actions для автоматичної публікації на GitHub Pages.

Застосунок має:

- працювати без сервера;
- не використовувати backend;
- не використовувати зовнішню базу даних;
- не вимагати авторизації;
- не надсилати дані в інтернет;
- працювати як статичний сайт на GitHub Pages;
- коректно працювати на телефоні, планшеті та комп’ютері.

Налаштуй `vite.config.ts` для розміщення у підкаталозі GitHub Pages. Не використовуй маршрутизацію, яка потребує серверного fallback. Можна використати один екранний flow або `HashRouter`.

## 2. Призначення першої версії

Перша фаза застосунку має лише одну мету:

> Допомогти Ксенії окремо оцінити продукти в обраних нею категоріях та отримати структурований список продуктів за рівнем складності.

Користувач не зобов’язаний оцінювати весь каталог.

Він може:

- обрати лише одну категорію, наприклад `Фрукти`;
- завершити оцінювання цієї категорії;
- переглянути та роздрукувати результат лише для неї;
- повернутися до інших категорій пізніше;
- ніколи не проходити категорії, які зараз не потрібні.

Кожна категорія повинна працювати як окреме завершене мініопитування.

Не реалізовуй у першій фазі:

- складання меню;
- рекомендації, що потрібно їсти;
- вибір порцій;
- підрахунок калорій;
- показ харчової цінності;
- вагу або BMI;
- план експозицій;
- рулетку продуктів;
- випадковий вибір продукту;
- нагадування поїсти;
- оцінювання «правильності» відповідей.

Додай до `README.md` розділ `Phase 2`, де коротко переліч:

- формування меню;
- список продуктів для майбутніх спроб;
- рулетку продуктів середньої складності;
- погодження експериментів із терапевтом або дієтологом.

Не реалізовуй ці можливості зараз.

## 3. Основний сценарій користувача

### Крок 1 — Головний екран

Покажи коротке повідомлення:

> Тут немає правильних або неправильних відповідей. Ти можеш обрати лише одну категорію, наприклад фрукти, оцінити її та зупинитися. Відповіді автоматично зберігаються.

Кнопки:

- `Обрати категорію`;
- `Продовжити незавершену категорію`;
- `Переглянути результати`;
- `Знайти окремий продукт`.

Кнопку `Продовжити незавершену категорію` показуй лише за наявності незавершеного оцінювання.

### Крок 2 — Вибір категорії

Покажи всі категорії окремими картками.

На кожній картці відображай:

- назву категорії;
- короткий опис;
- кількість продуктів;
- кількість уже оцінених продуктів;
- стан категорії;
- кнопку `Оцінити категорію` або `Продовжити`.

Стани категорії:

- `Не розпочато`;
- `У процесі`;
- `Оцінено`;
- `Частково оцінено`;
- `Пропущено`.

Категорія вважається оціненою, коли користувач дійшов до її фінального екрана. Пропущені продукти не заважають завершити категорію.

### Крок 3 — Оцінювання обраної категорії

Показуй лише продукти з обраної категорії.

Не переводь користувача автоматично до наступної категорії.

Після завершення категорії покажи:

> Категорію «Фрукти» завершено. Відповіді збережені. Тобі не потрібно зараз оцінювати інші категорії.

Кнопки:

- `Переглянути результати цієї категорії`;
- `Роздрукувати цю категорію`;
- `Повернутися до категорій`;
- `Завершити на сьогодні`.

Не показуй кнопку на кшталт `Перейти до наступної категорії` як основну дію. Її можна додати як необов’язкове нейтральне посилання:

- `Обрати іншу категорію`.

### Крок 4 — Результат категорії

Покажи результат лише для щойно завершеної або вибраної категорії.

Наприклад:

```text
Категорія: Фрукти

Оцінено: 18
Пропущено: 3
Не знайома з продуктом: 2
```

Дозволь:

- фільтрувати продукти за рівнем складності;
- змінювати відповіді;
- друкувати одну категорію;
- експортувати одну категорію;
- повернутися до загального списку категорій.

## 4. Мова інтерфейсу

Основна мова — українська.

Назви продуктів зберігай із такими полями:

```ts
interface FoodItem {
  id: string;
  nameUk: string;
  nameEn: string;
  aliases: string[];
  categoryId: string;
  storeTags: StoreTag[];
  keywords: string[];
}
```

```ts
type StoreTag =
  | "heb"
  | "phoenicia"
  | "common-us"
  | "eastern-european";
```

Пошук має знаходити продукти:

- українською;
- англійською;
- за поширеними російськомовними назвами;
- за транслітерацією;
- за альтернативними назвами.

Приклади:

- `гречка`, `buckwheat`, `buckwheat groats`, `kasha`;
- `сир кисломолочний`, `творог`, `farmer cheese`, `quark`;
- `вареники`, `vareniki`, `pierogi`;
- `сметана`, `sour cream`;
- `оселедець`, `селедка`, `herring`;
- `ряжанка`, `ryazhenka`, `baked milk`;
- `сирники`, `syrnyky`, `cheese pancakes`;
- `голубці`, `holubtsi`, `stuffed cabbage`;
- `деруни`, `draniki`, `potato pancakes`.

Пошук має:

- ігнорувати регістр;
- ігнорувати зайві пробіли;
- підтримувати частковий збіг;
- знаходити альтернативні назви;
- нормалізувати типові українські та російські назви;
- показувати найрелевантніші результати першими.

Не виконуй live-пошук на сайтах H‑E‑B або Phoenicia. Каталог має бути локальним JSON або TypeScript-файлом у репозиторії.

## 6. Локальний каталог продуктів

Створи початковий каталог приблизно зі 120–160 базових продуктів.

Головний принцип:

> Один запис має представляти окремий базовий продукт, а не готову страву, рецепт або незначну варіацію того самого продукту.

Не додавай до основного каталогу готові складні страви, наприклад:

- вінегрет;
- олів’є;
- борщ;
- суп із фрикадельками;
- голубці;
- деруни;
- сирники;
- котлети;
- тефтелі;
- млинці з начинкою;
- запіканки;
- торти за окремими назвами.

Такі страви користувач зможе додати самостійно через категорію `Мої продукти`, якщо вони важливі для її звичного харчування.

Не створюй багато незначних варіацій одного продукту.

Наприклад, замість:

- білий хліб;
- чорний хліб;
- житній хліб;
- бородинський хліб;
- багет;
- булочка;
- тостовий хліб;

додай базові позиції:

- `Хліб`;
- `Булочка`;
- `Лаваш або піта`.

Так само:

- не розділяй яблука на червоні та зелені;
- не створюй окремі записи для різних форм нарізання;
- не створюй окремі записи для різних брендів;
- не створюй окремі записи для кожного смаку йогурту;
- не створюй окремі записи для різної жирності молока;
- не дублюй один продукт під українською та англійською назвами.

Відмінності мають зберігатися в `aliases`, а не як окремі продукти.

- часто сприймаються як один продукт;
- регулярно продаються готовими;
- можуть мати окремий рівень складності;
- знайомі підліткам у США.

Приклади:

### Магазинні теги

Додай для продуктів приблизні теги:

- `heb` — продукти, які часто можна знайти у звичайному H‑E‑B;
- `phoenicia` — міжнародні або східноєвропейські продукти, які часто шукають у Phoenicia;
- `common-us` — поширені продукти в американських магазинах;
- `eastern-european` — характерні для східноєвропейського харчування.

Позначки магазинів мають бути допоміжними, а не основним способом організації каталогу.

Чітко зазнач у застосунку:

> Позначка магазину не гарантує, що продукт зараз є в наявності.

Не додавай:

- ціни;
- бренди;
- калорійність;
- розмір порції;
- відсоток жирності;
- харчову цінність.

## 7. Оцінювання продукту

Основне запитання:

> Наскільки складним для тебе здається цей продукт зараз?

Варіанти:

### Низька складність

> Зазвичай можу їсти без значної тривоги.

### Середня складність

> Може бути тривожно або залежить від ситуації.

### Висока складність

> Зараз викликає сильну тривогу або бажання уникнути.

### Не знаю

> Я не впевнена, як це оцінити.

### Не знайома з цим продуктом

> Не їла або не пам’ятаю.

### Не оцінювати

> Пропустити без пояснення.

Для внутрішньої моделі використовуй:

```ts
type DifficultyLevel =
  | "low"
  | "medium"
  | "high"
  | "unsure"
  | "unfamiliar"
  | "skipped";
```

Не перетворюй `unfamiliar`, `unsure` або `skipped` на високу складність.

Не використовуй у підлітковому інтерфейсі слова:

- `небезпечний продукт`;
- `поганий продукт`;
- `заборонений продукт`;
- `правильна відповідь`;
- `неправильна відповідь`.

---

## 8. Оцінка «рік тому»

Для кожного продукту дозволяй окремо відповісти:

> А приблизно рік тому цей продукт здавався тобі…

Варіанти:

- низька складність;
- середня складність;
- висока складність;
- не знаю;
- не пам’ятаю;
- не їла його рік тому;
- пропустити.

Пояснення:

> Це не тест пам’яті. Приблизна відповідь або «не пам’ятаю» — нормальні варіанти.

Зберігай поточну та ретроспективну оцінки окремо.

```ts
interface FoodAssessment {
  foodId: string;
  current: DifficultyLevel | null;
  oneYearAgo: PastDifficultyLevel | null;
  updatedAt: string;
}
```

```ts
type PastDifficultyLevel =
  | DifficultyLevel
  | "not-eaten-then"
  | "dont-remember";
```

Оцінка «рік тому» необов’язкова.

## 9. Захист від перевантаження

Опитувальник може бути психологічно виснажливим.

### Одна категорія за раз

Після вибору категорії не показуй продукти з інших категорій.

У верхній частині екрана показуй:

```text
Фрукти та ягоди
Продукт 4 із 24
```

Не показуй загальну кількість продуктів у всьому каталозі під час оцінювання однієї категорії.

### Короткі частини

Якщо категорія містить багато продуктів, поділи її на блоки по 8–10 продуктів.

Після кожного блоку показуй:

> Цю частину категорії завершено. Відповіді вже збережені.

Кнопки:

- `Продовжити цю категорію`;
- `Зробити перерву`;
- `Переглянути результат цієї частини`;
- `Завершити категорію зараз`.

Якщо користувач обирає `Завершити категорію зараз`, решту продуктів познач як `Не оцінено`, а не як `Пропущено`.

### Одна картка продукту

Показуй лише один продукт за раз.

На картці:

- українська назва;
- англійська назва меншим текстом;
- категорія;
- необов’язкові позначки магазинів;
- поточна оцінка;
- необов’язкова оцінка рік тому;
- кнопка `Далі`.

Не показуй фотографії продуктів у першій версії. Використовуй нейтральні іконки категорій.

### Навігація

Додай:

- `Назад`;
- `Далі`;
- `Пропустити`;
- `Зберегти й вийти`.

Автоматично зберігай відповідь одразу після вибору.

Користувач може змінити будь-яку попередню відповідь.

## 10. Аніме-стиль

Створи спокійний, сучасний інтерфейс із легким натхненням від аніме.

Вимоги:

- не копіюй конкретних аніме-персонажів;
- не використовуй захищені логотипи;
- створи оригінального маленького персонажа-помічника;
- персонаж має бути нейтральним і ненав’язливим;
- можна використати образ маленької лисиці, кота або духа-помічника;
- використовуй м’які форми, світлий фон і достатній контраст;
- анімації мають бути повільними та необов’язковими;
- підтримуй `prefers-reduced-motion`;
- не використовуй яскраві попередження або небезпечні символи для продуктів високої складності.

Приклади повідомлень:

- `Відповіді збережено.`
- `Можна завершити лише цю категорію.`
- `Інші категорії можна залишити на потім.`
- `Тут немає неправильних відповідей.`
- `Можна повернутися до цього продукту пізніше.`
- `Не пам’ятати — нормальна відповідь.`

Не використовуй:

- streaks;
- бали;
- рейтинги;
- таймер зворотного відліку;
- нагороди за певні відповіді;
- повідомлення, що тиснуть завершити весь каталог.

## 11. Пошук та додавання продуктів

Додай екран `Знайти продукт`.

Пошук працює лише по локальному каталогу.

Результат показує:

- українську назву;
- англійську назву;
- категорію;
- магазинні теги;
- поточну оцінку, якщо вона вже є.

Дозволь:

- оцінити знайдений продукт окремо;
- перейти до його категорії;
- не починати всю категорію.

Якщо продукт не знайдено, покажи:

> Не знайшла потрібний продукт?

Кнопка:

- `Додати свій продукт`.

Для власного продукту потрібно ввести:

- назву;
- необов’язкову англійську назву;
- категорію.

Власні продукти зберігай у `localStorage`.

## 12. Збереження у localStorage

Використовуй один версійований об’єкт:

```ts
interface CategoryProgress {
  categoryId: string;
  status:
    | "not-started"
    | "in-progress"
    | "completed"
    | "partially-completed"
    | "skipped";
  currentFoodIndex: number;
  assessedFoodIds: string[];
  completedAt: string | null;
}
```

```ts
interface AppStorage {
  schemaVersion: 1;
  assessments: Record<string, FoodAssessment>;
  customFoods: FoodItem[];
  categoryProgress: Record<string, CategoryProgress>;
  lastActiveCategoryId: string | null;
  preferences: {
    reducedMotion: boolean;
    showStoreTags: boolean;
  };
}
```

Ключ:

```ts
const STORAGE_KEY = "ksenia-food-assessment-v1";
```

Реалізуй:

```ts
loadAppStorage();
saveAppStorage(data);
resetAppStorage();
exportAppStorage();
importAppStorage(file);
exportCategory(categoryId);
```

Вимоги:

- безпечне читання JSON через `try/catch`;
- валідація структури;
- значення за замовчуванням;
- підтримка майбутніх міграцій;
- автоматичне збереження;
- підтвердження перед повним очищенням;
- окреме очищення результатів однієї категорії;
- можливість експортувати лише одну категорію.

Пояснення користувачу:

> Дані зберігаються лише в цьому браузері. Якщо очистити дані браузера або перейти на інший пристрій, вони не перенесуться автоматично.

## 13. Екран результатів

Створи два режими.

### Результати однієї категорії

Наприклад:

```text
Фрукти та ягоди

Оцінено: 18
Низька складність: 8
Середня складність: 5
Висока складність: 3
Не знаю: 2
Не оцінено: 6
```

Фільтри:

- `Усі`;
- `Низька складність`;
- `Середня складність`;
- `Висока складність`;
- `Не визначено`;
- `Не оцінено`.

### Загальний огляд

Показуй не один загальний результат, а список категорій:

```text
Фрукти та ягоди — оцінено
Овочі — не розпочато
Молочні продукти — у процесі
Солодощі — не розпочато
```

Не створюй відчуття, що всі категорії повинні бути завершені.

Не показуй глобальний відсоток на кшталт `12% усього каталогу завершено` як головний показник.

Для кожного продукту показуй:

- назву;
- категорію;
- оцінку зараз;
- оцінку приблизно рік тому;
- текстову зміну.

Варіанти зміни:

- `Стало менш складно`;
- `Без помітної зміни`;
- `Стало складніше`;
- `Недостатньо даних для порівняння`.

## 19. Критерії готовності

Робота вважається завершеною, коли:

- застосунок запускається без помилок;
- TypeScript не має помилок;
- production build успішний;
- GitHub Pages deployment налаштовано;
- каталог містить приблизно 120–160 базових продуктів без зайвих варіацій;
- пошук працює українською та англійською;
- пошук підтримує альтернативні східноєвропейські назви;
- можна додати власний продукт;
- кожна категорія відкривається окремо;
- можна оцінити лише категорію `Фрукти`;
- після завершення `Фруктів` інші категорії залишаються нерозпочатими;
- користувач не зобов’язаний проходити весь каталог;
- прогрес кожної категорії зберігається окремо;
- можна закрити сторінку та продовжити обрану категорію;
- можна завершити категорію з неоціненими продуктами;
- оцінка рік тому необов’язкова;
- результати можна переглядати окремо за категоріями;
- одну категорію можна окремо роздрукувати;
- одну категорію можна окремо експортувати;

- застосунок не надсилає дані назовні.

Згенеруй повний код усіх необхідних файлів. Не залишай `TODO`, псевдокод або порожні компоненти. Після генерації перевір логіку, TypeScript-типи, доступність, збереження в `localStorage` та сумісність із GitHub Pages.
